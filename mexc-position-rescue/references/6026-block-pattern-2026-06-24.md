# 6026 Block Incident Pattern (2026-06-24)

## Timeline
- **Root cause**: `close_position` used `side=4` (broken) → rapid open/close cascade → triggered risk control
- **Trigger time**: ~15:00 UTC (22:00 WIB), 2026-06-24
- **Duration**: 6.5+ hours (well beyond expected 30min-2hrs)
- **Status at session end**: STILL BLOCKED — user advised to generate new API key or contact support

## Critical Finding: 6026 is ACCOUNT-LEVEL, NOT IP-Level

**Tested routes (all return 6026):**
- CF Worker proxy → 6026 (before CF Worker itself died with 403)
- Direct api.mexc.com → 6026
- Direct contract.mexc.com → 403 (WAF blocks POST, but GET shows balance fine)

**Conclusion**: Proxy rotation does NOT help. The block is on the API key/account, not the connection IP. MEXC server-side risk control.

## What Was Tried
1. Waited 30min — still blocked
2. Bot killed to stop wasting API calls
3. Monitor cron set up (every 5 min) using MEXCClient from bot code
4. Multiple "check" attempts — each one = a test order that extends the block
5. **Tried different symbols** (ETH, BTC, DOGE, XRP, SOL, 1INCH) — ALL return 6026
6. **Tried different endpoints** (`/risk/control`, `/account/verify`, `/contract/verify`) — ALL return 404 Not Found
7. **Tried different proxies** (CF Worker, api.mexc.com, contract.mexc.com, api.mexc.kr) — ALL return 6026
8. **Tried different order params** (leverage=1, vol=1, price=0) — still 6026
9. **Tried User-Agent rotation** (Chrome, Safari, Android, MEXC app UA) — ALL return 6026
10. **Tried `change_risk_level` endpoint** — returns error 8817: "Risk limiting mechanism has been upgraded. Please check the website for more information"
11. **Tried MEXC regional endpoints** — api.mexc.kr (works, returns 6026), api.mexc.cc (403), api.mexc.me/.sg (don't resolve)

## No Programmatic Fix Exists

MEXC has NO API endpoint to:
- Check risk control status
- Request risk assessment
- Clear 6026 block
- Verify account standing

Only options:
1. **Wait** (could be hours to days)
2. **Generate new API key** in MEXC app → Settings → API Management
3. **Contact MEXC support** via app chat
4. **Check MEXC app** for pending risk assessment prompt

## CF Worker Death (Same Session)

CF Worker `mexc-proxy.refidsaputro369.workers.dev` started returning 403 Forbidden during this session. Bot was updated to use `api.mexc.com` direct. Confirmed working for both GET and POST.

## Prevention
- Always use `side=2` for close (NEVER `side=4`)
- Add 120s cooldown after any close failure before retry
- Rate limit: 1s between orders minimum
- Don't spam test orders during 6026 — wait and monitor passively
- Keep fallback endpoint (api.mexc.com) configured in case CF Worker dies
